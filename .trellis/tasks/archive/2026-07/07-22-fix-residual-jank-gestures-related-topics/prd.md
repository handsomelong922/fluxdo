# 修复剩余卡顿、手势冲突并添加相关帖子

## Goal

继续改善频繁浏览帖子后的流畅度，消除详情页右滑返回对文字选择和横向内容的干扰，并在主帖“相关链接”下方提供网页端同源的 5 条“相关帖子”，让连续阅读稳定、内容交互可靠、帖子发现能力完整。

## Confirmed Facts

- 新性能日志中最严重的首页帧为 638ms，其中 build 633ms；同一帧记录 24 个卡片标签并丢弃 245 个标签，下一帧又构建约 156 张卡片。
- 该卡顿发生在从帖子返回首页后，首页列表位于约 43893px 深处并执行回顶；现有“先 jump 到两个 viewport 再 animate”仍会使变高列表沿途物化大量卡片。
- 图片缓存峰值约 26.6MiB，未达到 72MiB 上限；MessageBus 4553ms 请求是长轮询，不是 638ms UI build 的根因。
- 详情页右滑返回由 route 外层原始 `Listener` 观察所有指针；它不参与 gesture arena，所以会与代码块横向滚动并行生效。
- 已有文字选择 blocker 只覆盖已产生非空选择后的状态，必须保留并补齐后代横向手势竞争。
- 2026-07-22 实际网页验证：滚到帖子末尾时请求 `GET /t/2444169/92.json`，响应同时包含 `related_topics` 和 `suggested_topics`，各 5 条；网页“相关”区只展示 `related_topics`。
- `related_topics` 条目包含 `id`、`title`、`slug`、`created_at`、`last_posted_at`、`posts_count`、`views`、`like_count`、`category_id`、`tags` 等字段。

## Requirements

- 远距离首页回顶的布局工作量必须与已加载列表长度无关，不能再通过普通 `jumpTo` 或长距离 `animateTo` 穿越变高列表。
- 保留首页已加载数据、滚动状态、缓存与正常路由生命周期；不能用清空列表或模拟重启掩盖卡顿。
- 普通内容区域右滑仍返回上一层级，普通左滑仍按现有偏好进入 AI 助手。
- 已选中文字后拖动任一选择手柄，不得触发 route 返回动画或取消选择。
- 代码块、WebView/iframe 及其他后代横向手势获得竞争时，route 返回不得并行生效；垂直滚动行为保持不变。
- 详情页只消费网页返回的 `related_topics`，不得用 `suggested_topics` 代替或混合。
- 相关帖子固定最多 5 条，按 `created_at` 降序排列，默认展开，并放在主帖“相关链接”区域下方；无数据或请求失败时不显示空壳且不影响正文/评论。
- 点击相关帖子使用项目统一的 `buildTopicDetailRoute(...)` 导航语义。
- Discourse UTC 时间继续通过 `TimeUtils` 解析，不直接使用 `DateTime.parse/tryParse`。
- 三个可独立验收的交付项分别提交，全部本地验证完成后再统一推送当前分支到 GitHub。

## Acceptance Criteria

- [ ] 从 40000px 以上深度触发首页回顶时，不会构建与中间列表长度成比例的卡片，且最终到达顶部。
- [ ] 首页回顶、刷新后回顶、再次点击当前 tab 三个入口共享同一有界实现。
- [ ] 已选中文字后向左或向右扩展选择均不触发返回或 AI 翻页。
- [ ] 代码块在可横向滚动方向拖动时只滚动代码；route animation 保持 1.0，页面不 pop。
- [ ] 普通页面区域右滑仍能完成返回，普通左滑 AI 入口行为保持通过。
- [ ] 详情响应中的 `related_topics` 被解析、按创建时间降序、截取 5 条并显示在主帖相关链接下方。
- [ ] `suggested_topics` 不出现在新增相关帖子区；空数组、缺字段、请求失败均安全降级。
- [ ] 相关帖子默认展开，标题可点击，并沿用统一详情路由。
- [ ] 相关定向测试、`flutter analyze --no-pub`、完整 `flutter test --no-pub` 和 `git diff --check` 全部通过。
- [ ] 本地提交保持一项改动一个 commit，最终一次性推送到 GitHub。

## Out Of Scope

- 不实现或展示“推荐”列表。
- 不改变论坛服务端的相关度算法，也不在客户端重新做关键词匹配。
- 不以清空全局图片缓存、首页列表或路由栈作为常规页面切换方案。
- 不重做详情页整体布局、评论排序或 AI 助手交互。
