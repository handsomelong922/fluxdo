# 修复相关帖子展示与首页/详情性能稳定性

## Goal

在不增加高频访问或阻塞帖子首屏的前提下，稳定展示网页端官方“相关”话题，并修复 Boost 高密度头像/表情面板卡顿以及首页分页偶发卡死，使连续浏览帖子时保持可恢复、低掉帧的体验。

## Confirmed Facts

- 现有 UI 已在主帖点赞、回复和更多操作按钮上方渲染 `RelatedTopics`，默认展开、只显示标题、最多 5 条并按创建时间倒序。
- 现有解析只消费官方详情响应中的 `related_topics`，不会把 `suggested_topics` 当作“相关”。
- 当前相关话题补取只在 `loadMore()` 恰好抵达末页时触发；初始已在末页或用户未滚到底部时不会触发，因此多数帖子不显示。
- 网页端切换“推荐/相关”不会额外发起独立列表请求；项目应继续从帖子详情响应的 `related_topics` 字段取数。
- 性能日志显示，移动端打开 Boost 输入框后默认挂载 EmojiPicker，图片存活数从个位数跃升到约 190，构成明确的构建和图片解码压力。
- 首页 `loadMore()` 只有在可见条目数增加时才推进页码；成功返回但过滤后为空或全部重复的页面会被反复请求。
- `/latest.json` 日志中的请求均返回 200；问题更符合客户端分页状态停滞，而不是服务端持续不可用。

## Requirements

### 1. 官方“相关帖子”

- 只读取 `related_topics`，明确忽略 `suggested_topics` / “推荐”。
- 每个普通帖子详情都应有机会获得相关话题，不依赖用户滚到评论末尾。
- 相关数据不得阻塞正文首屏：初始详情先完成展示，再以低优先级后台补取缺失字段。
- 补取必须使用服务端 `highest_post_number`，缺失时才回退到 `posts_count`，不得用当前已加载的最后一楼误判末页。
- 同一登录身份、同一 topic 和同一末楼编号的请求需要短期缓存与并发复用；禁止轮询、定时自动重试和快速重试。
- 可选后台请求失败不得让详情页进入错误态，不弹出加载失败，也不得覆盖已加载正文。
- 私信和详情筛选模式跳过相关话题补取。
- 用户主动滚到末页时可进行一次后备补取，但必须复用同一缓存/in-flight 机制。
- 最终展示最多 5 条，按 `created_at` 从近到远；标题点击通过共享详情路由进入目标话题。
- 首页、搜索、收藏、浏览历史及其他所有进入 `TopicDetailPage` 的入口行为一致。

### 2. 帖子进入速度

- 点击首页话题并启动详情路由前，立即暂停尚未启动的首页正文摘要预取；详情关闭后释放暂停令牌。
- 不取消已经发出的请求，不影响正文主请求，也不改变桌面双栏选择行为。
- 相关话题请求必须在正文首屏完成后再调度，且使用低优先级、静默请求选项。

### 3. Boost / 头像卡顿

- 移动端 Boost 输入框初次打开时只显示输入区，不实例化 EmojiPicker；用户点击表情按钮后才创建面板。
- 桌面端保留默认展开表情面板的现有体验。
- EmojiPicker 移动端预构建范围降到约 160 logical pixels，桌面端控制在约 480 logical pixels。
- Boost 气泡中的头像始终使用可推导的静态头像 URL，避免高密度 Boost 列表播放动态图。
- 移除 Boost 头像外层与 `SmartAvatar` 重复的头像策略监听，减少无效嵌套构建。
- 不改变全局“静态头像优先”开关对其他页面的产品语义。

### 4. 首页概率性加载失败

- 服务端成功返回下一页后，无论过滤/去重后是否新增可见话题，都必须推进客户端页码。
- 短暂网络错误只进入冷却，不启动定时请求；冷却结束后，仅在用户再次滚到底部时允许一次新请求。
- 401、403、419、429、Cloudflare/鉴权类错误保持手动重试，禁止自动恢复访问。
- 手动点击重试应立即清除失败门禁并重新请求当前下一页。
- 不在 Dio 既有 GET 重试之外叠加即时循环重试。

## Acceptance Criteria

- [x] 初始详情响应不含 `related_topics` 时，正文 Future 先完成；随后只发生低优先级补取并更新相关区域。
- [x] 初始响应已含相关列表或明确空列表时不产生补取请求。
- [x] `highest_post_number` 与 `posts_count` 不一致时，请求路径使用前者。
- [x] 同一身份/topic/末楼的并发及短期重复加载只产生一次网络调用；失败不污染缓存。
- [x] 私信、筛选模式、相关请求失败均不影响正文显示。
- [x] 相关区域默认展开、最多 5 条、创建时间倒序、标题可进入共享详情路由。
- [x] 首页点击进入详情时，摘要队列在 push 前暂停，并在 route 完成后释放。
- [x] 移动端 Boost 输入框首帧不存在 EmojiPicker，点击表情按钮后才出现。
- [x] EmojiPicker 移动端/桌面端 cacheExtent 分别受 160/480 左右的边界约束。
- [x] Boost 单个和分组头像均生成静态 URL，并且不再包含外层重复策略监听。
- [x] 下一页全部被过滤或去重时，下一次加载请求会访问后续页而不是重复当前页。
- [x] 短暂错误冷却后需由新的滚底动作触发；限流/CF/鉴权错误仍要求手动重试。
- [x] 定向测试、完整 `flutter test --no-pub`、`flutter analyze --no-pub`、格式检查和 `git diff --check` 通过。
- [x] 三类产品改动形成独立本地提交，完成全部验证后统一推送到当前 GitHub 分支。

## Out of Scope

- 不实现网页端“推荐”列表或推荐算法。
- 不轮询相关话题，不抓取网页 DOM，不绕过 Cloudflare，不使用自动化浏览器持续访问论坛。
- 不全局禁用所有动态头像，也不改变用户现有头像偏好设置。
- 不重做帖子详情 UI、首页筛选规则或 Dio 的整体认证/Cloudflare 流程。

## Open Questions

无阻塞问题；用户已明确要求实现、充分验证、本地提交后统一推送。
