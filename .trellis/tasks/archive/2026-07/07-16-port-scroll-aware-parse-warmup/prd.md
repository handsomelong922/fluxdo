# 手工移植滚动期间解析预热让路

## Goal

在不改变帖子加载、渲染和导航语义的前提下，让详情页后台帖子解析预热在用户滚动及惯性滚动期间主动让路，避免原子 HTML 解析任务挤占主线程滚动帧。

## Confirmed Facts

- 当前分支的详情页已在追加/前插帖子时通过 `_schedulePostParseWarmUp` 逐帖预热短帖 Gallery 信息、长帖 HTML chunk 和长帖渲染数据。
- 当前预热使用 `Priority.idle`，但没有检查全局 `ScrollBusySignal.isBusy`；idle task 仍可能在滚动帧间隙开始不可抢占的解析工作。
- 当前分支已有 `ScrollBusySignal`，其热路径只更新时间戳，不触发 Widget rebuild；其他后台任务已使用它在滚动期间让路。
- 当前详情页的渐进物化已经在滚动期间暂停，本任务不替换或削弱该策略。
- 当前分支没有上游新版自绘卡、`fluxdo_render` 子包或对应富文本架构，因此不得 cherry-pick 上游提交。

## Requirements

- 手工适配上游 `348f5fa9` 的滚动让路思想，不复制其与当前代码结构不匹配的实现。
- 在开始处理下一篇待预热帖子前检查滚动繁忙状态；繁忙时不消费队列索引、不启动短帖或长帖解析。
- 滚动繁忙时以有界 Timer 延迟重试；同一预热代只能保留一个待执行重试。
- 新一轮帖子预热、话题切换或页面销毁后，旧代任务不得继续解析或重新排队。
- 页面销毁时必须取消预热重试 Timer，避免销毁后的回调和资源残留。
- 预热异常继续静默降级到正式渲染路径，不得让页面进入错误状态。
- 保留现有长帖异步解析、短帖 Gallery 解析、缓存和诊断行为。
- 不修改首页帖子卡片、首页预览窗口样式、“首页详细展示”、预览首帖缓存、详情页首帖即时承接、显式目标楼层和评论渐进加载语义。
- 不修改网络请求数量、请求目标、Provider 身份、帖子排序、滚动位置或文本选择行为。
- 本次性能修复及其回归测试作为一个独立提交；Trellis 任务记录/规范若需提交，保持与业务修复分离。

## Acceptance Criteria

- [x] 滚动繁忙时，预热队列不增加已消费帖子数，也不调用帖子解析入口。
- [x] 滚动恢复空闲后，队列从原索引继续，且每篇帖子最多预热一次。
- [x] 新预热代启动后，旧代的延迟回调不会继续工作。
- [x] 页面销毁/任务取消后，延迟回调不会继续工作。
- [x] 预热解析抛出异常时仍继续后续队列，正式渲染兜底语义不变。
- [x] 相关定向测试、Dart/Flutter analyze 和完整 Flutter 测试通过。
- [x] Git diff 审核确认没有首页卡片、预览、首帖缓存、详情 Provider、网络服务或样式文件改动。
- [x] 工作区既有未跟踪文件未被暂存、删除或提交。
- [ ] 独立本地提交完成后，最终统一推送到当前 GitHub 分支。

## Out of Scope

- 不移植 `821f2722` 的敏感存储、选择系统、缓存范围或 LDC 凭证改动。
- 不移植 `fb1cf8a6` 相对时间时钟或上游自绘卡改动。
- 不修改首页详细展示的请求策略或详情页首帖复用策略。
- 不以减少功能、缩短内容、关闭图片或改变视觉样式换取性能。
