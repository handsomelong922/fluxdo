# 技术设计

## 测试边界

GitHub 原始 APK 是只读基准。运行载体固定为 `ctf_api30` 上已安装的 x86_64 direct 兼容包；不在本任务重新打包或替换官方资产。AVD 固定使用 AMD host GPU，避免把 SwiftShader 软件渲染噪声混入应用归因。

## 行为模型

通过 ADB 直接向 Android 设备注入触摸，不操作其他 Windows 窗口。每轮采用不规则中速滑动（约 550–1100ms）、短阅读停留（2–8s）、长阅读停留（10–20s）和一次短距离反向回看。页面进入后先等待内容稳定，再逐段阅读；不使用固定高频循环。

场景按“首页热身 → 文字帖 → 长帖/树形 → 图片/富媒体 → 多次返回后的首页 → 短暂后台再恢复”递进，观察是否出现随使用时间累积的持续退化。站点 429 时停止新页面请求，继续本地已加载内容或等待正常窗口恢复。

## 观测与分段

- 每轮开始和结束读取 `performance_trace.jsonl` 行数、PID 和前台 Activity。
- 使用截图与 `uiautomator dump` 确认页面和安全点击区域。
- 用外部场景记录映射日志行区间，不清空用户已有日志。
- 拉取新增 JSONL 后按 session、route、event、severity、dominantPhase、attributionHint、build attribution、imageCache 和请求事件聚合。
- 结合 SurfaceFlinger/GLES、crash buffer 和应用日志区分宿主 GPU、Flutter build/raster、网络/429 和 native crash。

## 修改门禁

只有候选热点同时满足以下条件才进入实现：

1. 在至少两轮相似正常操作中重复；
2. 与手势/路由时间区间吻合；
3. 有组件、图片、资源或 UI isolate 证据，而非仅有网络耗时；
4. 现有历史修复和测试尚未覆盖该状态转换；
5. 能在不改 UI/功能语义的前提下形成最小修复和回归测试。

若证据只指向模拟器 raster 基线或外部限流，则保留源码不动。若修改后同场景无量化改善，回滚修改。

## 兼容与安全

- 不进行社区写操作，不触碰敏感配置。
- 不改变卡片/详情/树形视图的布局、颜色、内容或交互。
- 不把 direct 兼容包缺少的高级网络原生库纳入本次修复。
- 所有代码提交只包含证实热点的产品/测试文件和本任务 Trellis 记录，用户现有未跟踪文件保持隔离。
