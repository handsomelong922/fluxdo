# 彻查性能日志并修复刷帖卡顿

## Goal

根据 `D:/Share files/Feem/performance_trace.jsonl` 的帧级证据，修复复杂帖子尤其树形评论模式中持续掉帧和触摸不跟手的问题，同时保持帖子内容、评论结构、手动展开能力、首页详细展示、预览承接和现有视觉样式不变。

## Confirmed Facts

- 日志包含 2019 条有效记录、309 条采样慢帧、61 个帧窗口和 11 次 UI isolate stall；设备为 120Hz。
- 话题 `1585027` 以树形模式进入后出现 `996ms` 冻结帧，其中 build `959ms`；同一时刻 image cache 报告 68 个 live image、56 个 pending image。
- 话题 `2547158` 以树形模式进入后逐步退化到连续 138 个慢帧，后续窗口接近每帧都慢，主要耗时在 raster/pipeline；image cache 从约 67.9MB 增至 71.7MB。
- `NestedPostList` 仅在根节点使用 `SliverList`；每个 `NestedPostCard` 用递归 `Column` 一次构建已展开的全部后代，后代即使远离视口也保持挂载。
- 少量回复会在每一层递归自动展开，已挂载的动画图片 provider 只在失去 listener 后暂停，因此树形根子树可让大量离屏图片/动画继续参与渲染。
- `NestedPostCard` 的 `RepaintBoundary` 包住整个递归子树，可能形成大范围嵌套重绘/合成边界；这与持续 raster 慢帧相符。
- 图片查看器另有一次约 1.25 秒的原图 raster 冻结，属于独立问题，不应和刷帖持续卡顿混成一个未经验证的修改。
- 无登录公开话题接口返回 403，不能安全核对具体媒体类型；本次不使用用户 Cookie 或绕过站点风控。

## Requirements

- 树形评论只允许视口内帖子自动物化其少量子回复；离屏后代不得因为递归默认展开而提前构建、解码或维持动画 listener。
- 用户手动展开评论时必须立即显示对应子回复，不能把显式操作改为延迟或取消。
- 自动加载子回复必须继续在滚动期间暂停，并且只有帖子进入视口后才可排队；离开/销毁后不得执行旧节点任务。
- 已经物化的可见子树在滚动过程中不得被主动折叠或删除，避免内容跳动和用户状态丢失。
- 将重绘隔离限制在单个帖子主体，不得用一个 `RepaintBoundary` 包住整个递归后代子树。
- 保持树线、头像、间距、操作栏、排序、加载更多、跳帖、已展开状态缓存和回复顺序不变。
- 增加轻量诊断事件，后续日志能确认树形子节点何时、在何深度、以多少数量被物化；诊断关闭时必须为空操作。
- 不修改首页卡片样式、首页详细展示、首帖立即承接、普通平铺详情或网络请求策略。
- 图片查看器的独立冻结只记录为后续证据点；没有尺寸/媒体证据前不牺牲原图缩放清晰度。

## Acceptance Criteria

- [x] 纯逻辑测试证明自动子节点工作必须同时满足：已展开、当前可见、未滚动暂停、未达到最大深度。
- [x] 树形列表首次进入时不再递归同步构建所有自动展开后代；可见父帖在首帧后渐进显示直接子回复。
- [x] 离屏节点不会发起自动子回复加载；进入视口后可恢复，用户手动展开仍立即生效。
- [x] 整个递归子树不再由单一外层 `RepaintBoundary` 包裹，单帖主体仍有局部重绘隔离。
- [x] 展开状态、回复缓存、树线布局、跳帖映射、加载更多和可见帖子上报相关测试通过。
- [x] 性能诊断测试覆盖新增树形物化事件，关闭诊断时无额外持久化开销。
- [x] 定向 analyze/tests、全量 `flutter analyze --no-pub` 和全量 `flutter test --no-pub` 通过。
- [x] 运行时代码按独立根因分开本地提交，不混入用户已有未跟踪文件。

## Out of Scope

- 修改首页帖子卡片视觉样式或首页详细展示逻辑。
- 重写整个树形评论为扁平化 Sliver 数据模型。
- 使用用户登录态抓取受保护话题。
- 在缺少证据时降低全局刷新率、禁用所有动图或降低图片查看器原图质量。
