# 修复相关帖子空值回归并统一详情入口

## Goal

修复上一轮“相关帖子”功能引入的详情解析回归，使首页帖子、首页预览、搜索、我的收藏和浏览历史等任何入口都能稳定打开帖子，并在主帖正文底部展示官方 `related_topics` 数据。

## Confirmed Facts

- 回归由上一轮新增的“相关帖子”功能引入。
- 首页正文预取和预览弹窗共用 `GET /t/{topicId}/1.json` 和 `TopicDetail.fromJson`，当前真实响应会触发 `type 'Null' is not a subtype of type 'int' in type cast`。
- 搜索等入口可能从命中楼层请求或无预览种子进入，因此没有稳定复现同一数据形状。
- 产品要求不变：只消费 `related_topics`，不消费 `suggested_topics`。

## Requirements

- 真实 `related_topics` 响应中的空值、缺失字段或单条异常数据不得使整个 `TopicDetail` 解析失败。
- 无法形成有效话题导航目标的相关条目应被忽略，其他有效条目仍需展示。
- `related_topics` 缺失与显式空列表的状态语义必须保持，不得破坏长帖到达末页后的补取逻辑。
- 相关帖子位于主帖正文的相关链接之后，默认展开，只显示标题，最多 5 条，按 `created_at` 倒序。
- 从首页点击、首页预览“查看详情”、搜索、我的收藏和浏览历史打开的详情页必须共享同一相关帖子行为。
- 相关数据加载失败或全部无效时只隐藏相关区，不得导致主帖、回复或预览弹窗加载失败。
- 将“详情页共享改动必须覆盖所有入口”和外部响应容错要求记录到 Trellis 项目规范。

## Acceptance Criteria

- [x] 能用至少一个真实形状失败夹具稳定复现旧实现的 `Null -> int` 异常，修复后测试通过。
- [x] 有效与无效相关条目混合时，详情正常加载且只保留有效条目。
- [x] `related_topics` 缺失、为 `null`、为空列表、为非列表或条目字段不完整时不得阻断主帖。
- [x] 相关帖子仍只消费官方 `related_topics`，默认展开，按创建时间倒序，最多 5 条，点击使用统一详情路由。
- [x] 首页预取/预览、普通详情、搜索、我的收藏、浏览历史入口均有自动化合同或等价集成验证。
- [x] 相关补取失败仍保留已加载的末页回复。
- [x] 定向模型、service、provider、widget、路由入口测试通过，完整 `flutter analyze --no-pub` 和完整 `flutter test --no-pub` 通过。
- [x] `git diff --check` 通过；提交和推送边界将在收尾步骤复核。

## Out Of Scope

- 不展示“推荐” `suggested_topics`。
- 不实现客户端相关度算法。
- 不修改相关帖子区的已确认产品样式。
