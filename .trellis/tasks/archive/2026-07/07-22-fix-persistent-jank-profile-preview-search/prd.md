# 修复持续卡顿并优化主页预览与搜索体验

## Goal

根据 2026-07-22 真机性能追踪，消除连续浏览和首页长列表操作后的持续卡顿，同时完成用户主页默认标签、帖子预览回复数视觉层级和搜索即时输入三项明确体验改进。

## Confirmed Facts

- 性能追踪来自魅族 21、Android 16、120Hz，会话保留约 448 秒至 951 秒的记录；其中有 261 个慢帧、5 次 UI isolate stall 和 2 次系统内存压力事件。
- 最坏首页帧为 332ms，其中 build 319ms；归因记录显示同一帧构建至少 259 张话题卡片，随后列表从约 4148px 跳到顶部。
- 当前首页使用变高 `ListView.builder`，显式回顶仍对任意距离直接 `animateTo(0)`。列表已经累计 259 个话题时，动画沿途物化大量卡片，成本随会话中加载的话题数量增长。
- 本次追踪中普通帖子页和返回后的首页都存在慢帧；框架图片缓存大多数时间约 10MB，图片查看器退出后也从约 33MB回落，不能再把持续卡顿简单归因于图片缓存或 MessageBus 长轮询。
- 帖子页现有销毁逻辑已经取消 timer/listener/MessageBus、清理移动端 HTML 运行期缓存；详情 provider 移动端保留窗口为 4 秒，详情快照还有条目与内容预算。
- 用户主页共有“总结、动态、话题、回复、点赞、回应”六个标签，当前 `TabController` 默认索引为 0。
- 帖子预览底栏保持左中右三部分，回复数目前与其他统计共用 13px 图标和 10px 文本。
- 搜索页进入后会请求论坛 `/u/recent-searches.json`，请求完成前用整页 loading spinner 替代空状态；这正是输入框出现后仍有明显等待感的来源。

## Requirements

- 子任务 `07-22-fix-browse-session-jank` 修复长列表回顶的会话长度相关成本，并保留帖子返回栈、首页详细展示、滚动位置和现有加载更多语义。
- 子任务 `07-22-default-user-profile-topics` 让任何头像入口打开的用户主页默认选中“话题”，并立即加载话题数据；其他标签仍可正常切换。
- 子任务 `07-22-emphasize-preview-replies` 保持预览底栏三栏结构和“查看详情”主操作不变，只强化回复图标与数字的视觉层级，确保 0 回复清晰可见。
- 子任务 `07-22-instant-search-input` 让搜索页首帧即可聚焦输入，取消进入页面时的远端历史请求和整页 loading；最近搜索改为本地持久化。
- 四项改动各自定向验证并按独立行为边界提交，不混入现有未跟踪 Trellis、密钥或用户文件。

## Acceptance Criteria

- [x] 超过多个 viewport 的首页回顶不会再沿整条列表动画并同步构建全部中间话题卡片；短距离回顶仍保持平滑动画。
- [x] 连续打开、返回帖子后，首页正常滚动和回顶的成本不随已加载话题总数线性增长；帖子详情销毁与缓存边界保持有效。
- [x] 打开任意用户主页时默认高亮并展示“话题”，首次进入会发起话题 filter 数据加载。
- [x] 预览底栏回复图标和数字明显大于浏览、点赞和时间统计，0 回复无需细看即可辨认，窄屏无溢出。
- [x] 点击首页搜索后输入框可立即聚焦输入，空查询页面不显示历史加载 spinner，也不请求或清除论坛云端搜索历史。
- [x] 本地最近搜索支持去重、最新优先、数量上限和本地清空；真正提交搜索时才发送论坛搜索请求。
- [x] 相关定向测试、全量 `flutter analyze --no-pub`、全量 `flutter test --no-pub` 和 `git diff --check` 通过。
- [x] 四个子任务按独立改动提交，父任务完成集成复核。

## Out of Scope

- 改变 MessageBus 长轮询协议、刷新率或网络 adapter。
- 清空全局图片缓存、禁用首页详细展示、图片、视频、复杂 HTML 或帖子返回栈。
- 重设计用户主页全部标签、帖子预览主体或搜索结果页。
- 将论坛服务端已有的搜索行为改造成新的同步服务。
