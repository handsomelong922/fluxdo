# 手工移植上游性能优化并审计首页请求风险

## Goal

在不改变现有功能、首页卡片样式、预览窗口交互和“首帖立即呈现、回复渐进加载”契约的前提下，手工适配 7 月 13–14 日上游的五项高价值性能改进，同时查清启动和首页详细展示的请求放大链，降低被站点识别为自动化行为的风险。

## Confirmed Facts

- 当前分支已有移动端话题卡片轻量壳，不得用上游 `topic_card.dart` 重构覆盖。
- 首页详细展示已支持卡片主帖摘要、预览种子写入、进入详情页后立即呈现主帖并后台重验。
- 开启首页详细展示时，`PreheatGate` 最多预热 8 个 `/t/{topicId}/1.json`，首页卡片又通过另一个 loader 按可见项加载，两者不共享 in-flight 去重，存在启动重复请求窗口。
- 开启时持续滚动会为每个新挂载且无缓存的话题发送主帖请求；这是高频主帖读取的主要来源。
- 关闭该功能后，启动预热会在读取开关后直接返回，卡片不构建摘要 loader；旧摘要缓存可用于用户点击时的详情首屏承接，但不会因读缓存而发起网络请求。
- 当前 `/latest` 回调仍会在 `MessageBusInitNotifier` 之外再次转发到追踪状态机，存在重复处理。
- 当前已有 `ScrollBusySignal`、性能诊断服务、图片尺寸约束和详情页多项等价优化，移植必须避免重复机制。

## Requirements

1. 移除 `/latest` 的重复追踪转发，保留 incoming 话题计数、静音分类过滤和 MessageBus 统一追踪更新。
2. 在滚动繁忙时延迟可延迟的 MessageBus 投递，但必须严格 FIFO，不得在队列满时插队，不得在停止/登出/销毁后投递旧会话消息，排空必须分批让出 UI isolate。
3. 对 Flutter 标准图片解码首帧建立可取消的并发闸门；必须包含 codec 排队期 dispose 防护，不改变 AVIF/贴纸/现有动图自有管线，不强制升级依赖。
4. 仅提取首页优化中不改视觉/交互的部分：页面层分类表快照传递、Emoji 无冒号快速路径及与当前卡片结构兼容的优化。不修改卡片样式、标签图标、间距、透明度和预览热区。
5. 详情页仅补充当前分支缺失的头像主题缓存失效；不覆盖已有精确 Riverpod select、渐进物化、预览种子和帖子身份稳定性逻辑。
6. 彻底审计启动后的网络请求类型、触发条件和周期请求，区分用户主动、启动必需、长轮询、后台低优先级和首页摘要请求。
7. 消除首页摘要的双 loader 启动重复请求；开启功能时仍保留可见卡片摘要和详情页首帖承接，但不得启动无界预抓取。
8. 关闭首页详细展示时，启动和首页滚动不得发起 `/t/{topicId}/1.json` 摘要请求；点击预览或话题详情仍可按用户交互正常请求。
9. 每个独立改动分开本地提交；全部验证后一次推送当前分支到用户 GitHub。

## Acceptance Criteria

- [x] 新增测试证明每条 `/latest` 追踪消息只进入追踪状态机一次，incoming 计数仍正常。
- [x] MessageBus 延迟队列测试覆盖 FIFO、滚动期不投递、静默后分批投递、超限不插队、`stopAll`/`dispose` 不泄漏。
- [x] 图片解码闸门测试覆盖并发上限、首帧限流、后续帧旁路和排队期 dispose。
- [x] 首页详细展示关闭时，构建/滚动首页不会调用主帖预览 fetcher。
- [x] 首页详细展示开启时，不再由 `PreheatGate` 启动第二个 loader 预抓取，可见卡片仍可渐进显示摘要。
- [x] 已有摘要/预览内容进入详情页时仍立即渲染首帖，并且评论和可变元数据仍后台重验。
- [x] 首页话题卡片的尺寸、颜色、圆角、间距、图标、标签、点击/长按/右侧预览热区均不变。
- [x] 启动请求审计形成可交付的路径清单和风险结论。
- [x] 定向 `flutter analyze`、相关单测/组件测试、全量 `flutter analyze --no-pub` 和全量 `flutter test --no-pub` 全部通过。
- [x] 提交历史保持一个独立改动一个 commit，不混入无关未跟踪文件，远端分支保留相同边界。

## Out of Scope

- 不移植上游卡片 WidgetSpan/图标字形化和任何样式变更。
- 不引入上游富文本 composer、`fluxdo_render`、媒体全家桶、动画 SVG 或自绘书签卡。
- 不改变用户配置的全局请求调度参数，不以牺牲所有前台请求速度代替对首页摘要的定向治理。

## Open Questions

无。用户已明确要求开始手工移植、充分验证、分开本地提交后推送。
