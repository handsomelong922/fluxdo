# 技术设计

## 边界

- 预览尺寸只修改共享 `TopicPreviewDialog`，因此首页、书签、历史和搜索继续自动统一。
- 私信修复只修改详情页对“是否实际使用树形视图”的判定，不修改通知导航和网络协议。

## 预览尺寸数据流

1. 安全视口高度计算最大值（现有 85%）和最低值。
2. 弹窗主体使用最小/最大约束，正文滚动区使用 loose flex，按真实渲染内容自然收缩或扩张。
3. 加载态至少占最低高度；正文到达触发 rebuild 后由 `AnimatedSize` 平滑插值。
4. 带自定义 actions 时为主体与 actions 分配同一总高度预算，避免总高度越界。

不采用 `IntrinsicHeight`，因为复杂 HTML、代码和图片会放大重复布局成本。

## 私信详情数据流

引入一个纯判定：只有“用户请求树形视图 && detail 已加载 && 非私信”时才 watch 和渲染 `nestedTopicProvider`。私信始终走现有 `TopicPostList`，普通话题不变。

## 回滚

- 预览提交可单独回滚，恢复固定高度和旧边框。
- 私信提交可单独回滚，恢复原 `_isNestedView` 判定。
