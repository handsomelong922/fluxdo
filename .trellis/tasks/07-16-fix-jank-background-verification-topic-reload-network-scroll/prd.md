# 修复复杂场景卡顿、后台验证、详情二次白屏与网络设置滚动跳变

## Goal

根据 2026-07-16 用户提供的性能与应用日志，修复复杂帖子/页面切换后仍存在的掉帧与不跟手，并消除 Cloudflare 验证前台白屏弹窗、书签/搜索进入详情后的二次整页白屏，以及网络设置列表的非手势跟随跳动，同时保持现有阅读体验与功能行为。

## Confirmed Constraints

- 必须保留首页详细展示、卡片已加载首帖向详情页即时承接、评论渐进加载的现有逻辑。
- 不得修改首页帖子卡片样式，也不得通过删除功能、隐藏内容或降低体验规避性能问题。
- Cloudflare 验证应在能够自动完成时完全后台运行，不显示短暂白屏弹窗干扰用户。
- 首页、书签、历史、搜索进入详情应共享一致的首帖承接与渐进加载体验。
- 修复必须基于日志与当前分支代码，不照搬上游实现。
- 四项独立修复分别提交；全部验证完成后一次性推送 GitHub。

## Confirmed Facts

- `performance_trace(1).jsonl` 共 412 个帧聚合/慢帧记录，最高 195ms；复杂帖子仍出现单帧 2–4 次 `nested:childrenMaterialized`，对应 30–57ms build。
- 正文图诊断记录到 `widthPx=1898`，而设备物理宽度为 1080；图片缓存增长至约 75.1MB，逼近 72MiB 配置上限，并出现 194ms raster 帧。
- `app_log_share.jsonl` 中 `/topics/timings` 在 CF 403 后仍约每 7 秒触发挑战检测；`ScreenTrack` 尚未使用 `CfChallengeService` 已提供的冻结信号。
- 启动 WebView session bootstrap 被 CF 403/429 挡下后，`BrowserTrustCoordinator` 明确以 `forceForeground=true` 调用验证页，导致启动前台弹窗。
- 搜索/书签的预览已写入首帖 seed，但带目标楼层请求返回的帖子窗口可能不含 1 楼；树形数据尚未完成时现有 UI 因无法从该窗口构造 OP 预览而显示骨架屏。
- 网络设置日志中滚动范围在一次手势期间从 1329.8 变化到 1840.9；`DebugToolsCard` 首帧异步读取已初始化的 `developer_mode`，随后插入多行控件，是主要高度突变来源。

## Requirements

1. 全面分析 `performance_trace(1).jsonl`、`app_log_share.jsonl` 和启动请求耗时榜，识别剩余卡顿的具体组件、阶段和触发链，并实施最小针对性修复。
2. 将启动期间可自动通过的 Cloudflare 验证改为不可见后台流程；不得破坏需要用户交互的真实挑战、登录状态或 Cookie 同步。
3. 修复从书签与搜索预览进入帖子详情时，已承接首帖被异步完整数据覆盖后触发的整页刷新/白屏；首帖应立即保留显示，评论区增量补齐。
4. 修复网络设置中最大并发数、窗口请求上限、窗口时长、请求最小间隔区域在慢速反向滚动时突然跳动；滚动位置必须持续跟随手势。
5. 对性能诊断字段做必要增强时，应保持低开销，并能将新发现的慢帧归因到具体组件或状态转换。

## Acceptance Criteria

- [x] 日志中的高耗时帧、图片/缓存压力、网络请求或导航状态异常均有可验证的根因说明，代码修复与根因直接对应。
- [x] 复杂帖子、跨页面切换及返回后的列表不再因本次定位到的同步重建/资源生命周期问题产生持续卡顿。
- [x] 网络不佳且验证可自动完成时，不出现用户可见的 Cloudflare 白屏弹窗；验证成功和会话同步仍正常。
- [x] 若遇到确实需要人工交互的挑战，仍有安全的显式验证兜底，不造成无限等待或登录失效。
- [x] 从书签和搜索的预览进入详情后，已加载首帖立即显示且不被整页白屏替换，评论按现有逻辑渐进加载。
- [x] 首页、历史记录等既有入口行为无回归，首页详细展示与卡片样式完全不变。
- [x] 网络设置慢速上下滚动无自动吸附或突跳，各数值控件仍可正常调整并持久化。
- [x] 定向测试、相关回归测试、Flutter analyze 及可执行的全量测试通过，无调试残留。
- [x] 每项独立修复形成独立本地提交，最终推送后本地与远端分支同步。
