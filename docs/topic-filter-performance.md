# 大规则集标题过滤优化

## 范围与行为

基线：`c5c69f92`。优化字面关键词匹配，不修改用户正则、规则数量限制、忽略列表或自动续页策略。

核对结果：

- 本地屏蔽用户已经由偏好设置惰性归一化为不可变 Set，每个作者走集合查找；没有把 300 个用户名逐个扫描的问题。
- 正则已在可终止 isolate 中编译、匹配，控制器缓存标题结果，分页只提交未知标题。保持现有两秒超时、取消、失败显示和待验证标题隐藏机制。
- 原字面匹配在每次列表重建与分页对全部已加载标题逐条扫描关键词，重复转小写与判断完整词属性。此前没有字面结果缓存。

新实现使用关键词前缀索引，预计算完整词属性，并缓存标题对应的首条命中规则（包含未命中结果）。缓存最多 2048 个标题且总计最多 262144 UTF-16 单元；超长标题完整匹配但不缓存。极长共同前缀触发等价的原生 indexOf 回退，防止前缀扫描退化。

只保留一套关键词索引；按规则内容与完整词开关失效，支持原地修改列表。清空所有过滤时释放索引。缓存不保存话题对象、作者或正则结果，因此每次仍重新判定屏蔽用户、已确认正则、待验证状态；不缓存整份可见/忽略列表。命中归因仍是屏蔽用户优先，其次输入顺序最早的关键词，最后正则。大小写、ASCII 完整词边界、空规则、重复规则、Unicode 与字面标点语义不变。

## 可复现验证

在仓库根目录执行（无需 Flutter 即可运行前四项）：

```sh
dart tool/topic_keyword_matcher_smoke.dart
dart tool/topic_keyword_filter_benchmark.dart
dart tool/topic_keyword_filter_benchmark.dart --cold
dart tool/topic_regex_smoke.dart
dart tool/topic_regex_filter_smoke.dart
flutter test test/utils/topic_keyword_matcher_test.dart test/utils/topic_keyword_filter_test.dart test/utils/blocked_user_filter_test.dart
```

结果：

- 14400 组确定性随机对照，与基线算法比较首次和缓存命中；覆盖完整词开关、中英文、Unicode、emoji、重复/空规则、首条规则归因、标题更新、规则原地修改、淘汰、超长标题、长共同前缀回退，全部通过。
- 500/1000 条规则、300 用户、40 页规模基准，每轮校验相同的预期过滤计数，全部通过。
- 既有正则烟测 14 项、控制器烟测 15 项全部通过，包括恶意回溯取消/超时与分页缓存。
- 独立 matcher 和两个新增命令行工具的 `dart analyze` 无问题。
- 新增 Flutter 集成回归覆盖分页、忽略原因、异步正则结果变更、同 ID 标题修改、原地规则修改。当前环境未安装 Flutter，尚未执行 Flutter 测试；不得视作已通过。

## 测量

2026-10-15，Linux x64 容器，AMD EPYC 9V74，Dart 3.13.3 stable JIT。各算法预热一次，随后七次取中位数，包含构建索引、规则快照比较、屏蔽用户 Set 查询和字面匹配。每页新增 30 个标题，共 40 页/1200 标题；每页重查全部已加载标题，共 24600 次访问。正常标题占多数，每七条一条末尾关键词命中，每十一条一条屏蔽用户。基线算法直接保留在烟测工具中，供对照，未修改其匹配逻辑。

## 余留风险

- 冷启动构建索引仍在主 isolate，复杂度与关键词总字符数成正比；大量超长字面规则需要真机 profile 再评估后台构建。
- 标题缓存有明确容量；词典索引大小仍与用户规则总长度成正比，没有新增限制或丢弃规则。
- 仍需遍历当前话题以保持作者变化、去重和最新过滤原因正确；这里只移除了昂贵的重复关键词匹配。
- 多个页面若使用不同规则集会置换唯一缓存，但不会错误复用结果。正常首页、分类、标签页共享同一组偏好规则。
